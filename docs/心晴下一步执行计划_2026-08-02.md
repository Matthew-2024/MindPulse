# 心晴 MindPulse 下一步执行计划

- 制定日期：2026-08-02
- 适用版本：当前 Web/iOS 原型、漂流瓶本机 Demo 和下一阶段校园试用准备版
- 依据：`docs/竞品市场研究与创新策略报告_2026-07-31.md`、当前代码、现有回归测试和已完成的视觉壳体调整
- 当前约束：截止日前剩余 5 天
- 计划目标：把竞品调研转成可以实现、可以测试、可以答辩的产品证据

## 0. 先给结论

接下来不再继续堆叠情绪日记、AI 聊天、冥想内容或社区功能。这些能力已经被 Daylio、Stoic、Bearable、MindDoc、Wysa、Youper、Headspace 和 7 Cups 等不同路线覆盖，心晴没有必要在 5 天内正面复制它们。

心晴下一步要证明的是一个更窄、也更有辨识度的任务：

> 当大学生发现自己的状态不太对劲时，心晴能否先判断信息够不够，再说明是否偏离自己的节奏，由 Safety Gate 决定当前允许的行动，并在需要时帮用户用最少的信息向真实的人开口。

因此，截止日前的唯一主线是：

```text
低负担记录
  -> 数据是否足够
  -> 是否偏离自己的节奏
  -> 当前允许什么行动
  -> 必要时生成最小披露求助表达
  -> 用户主动复制、发送或删除
```

漂流瓶 Demo 保留，但只作为“匿名连接感”的辅助演示，不作为产品主创新，也不包装成真实社区。

## 1. 竞品报告转出的工作结论

| 竞品观察 | 对心晴的启发 | 当前动作 |
|---|---|---|
| Daylio、Stoic 的记录入口很轻 | 记录速度是基础门槛，不是创新点 | 保持 1 分钟左右完成，不再增加字段 |
| Bearable 已经证明多信号和相关性有市场 | 情绪、睡眠、活动、连接感不是独家能力 | 把重点放在个人基线和行动含义 |
| Wysa、Youper、Headspace 已公开安全系统和危机转介 | “我们更安全”不能作为差异化口号 | 证明每个普通入口都不可绕过 Gate |
| 7 Cups 拥有真人倾听和社区网络效应 | 真实社区不是当前资源优势 | 漂流瓶维持本机 Demo，不做多人上线 |
| MindDoc 进入医疗器械和临床研究语境 | 心晴不能模仿医疗化承诺 | 坚持非诊断、非疗效、非危机预测 |
| 市场普遍使用“匿名、加密、安全”等宣传词 | 隐私必须变成用户可检查的行为 | 做判断收据、分享收据、导出和删除边界 |
| 支持平台解决“有人可以听” | 心晴可以解决第一次开口前的转译 | 把 Campus Warm Handoff 做成核心演示 |

## 2. 当前基线与明确缺口

| 能力 | 当前已有 | 还缺什么 | 优先级 |
|---|---|---|---|
| 低负担记录 | `CheckinPage` 已有情绪、睡眠、活动、连接感、备注 | 从空白档案验证耗时、字段负担和数据模式标识 | P0 |
| 演示数据与匿名记录 | `synthetic-demo`、`real-trial`、`empty` 已有区分 | 需要从清空后的档案完整走三条路径，证明没有混用 | P0 |
| Personal Rhythm | 有个人基线、偏移、完整度和置信度 | 5 天内先补解释与测试；7/14 天窗口、特殊时期延期 | P0/P1 |
| Safety Gate | `evaluateState`、`risk-gate`、高风险求助重定向已存在 | 数据不足直达普通入口的边界、深链接和直接调用矩阵仍要补齐 | P0 |
| 决策可解释 | 首页、Insight、DecisionTrace 已展示依据 | 统一三态演示和稳定测试断言 | P0 |
| Warm Handoff | `HelpComposer` 支持对象、需求、紧迫度、编辑和复制前预览 | 结构化分享收据、复制时间、字段清单、资源失效验收 | P0 |
| 隐私与数据台账 | 本机优先、导出、删除、资源核验已有 | 导出缺少漂流瓶数据；判断/分享收据还没有正式数据结构 | P0 |
| 行动记忆 | 已记录行动前后主观变化，并排除高风险学习 | 行动难度和再次尝试意愿延期 | P1 |
| 校园资源 | 有地区、热线、校内支持、服务时间、核验状态 | 先做单校配置模板和责任人机制，不做学校后台 | P1 |
| 漂流瓶 | 已完成本机投放、捞取、回复、隐藏、举报 | 只需补导出/删除验收和数据边界，不扩展真实社区 | P0 |

### 本阶段的三个硬缺口

1. **Gate 入口缺口**：当前高风险有全局重定向，但数据不足和 `/bottle` 等普通入口需要纳入同一套“允许动作”矩阵。
2. **Privacy Receipt 缺口**：当前求助页有可见文案，但 `HelpDraftEvent` 还没有完整记录本次判断、分享字段和复制动作的结构化收据。
3. **数据导出缺口**：设置页的 JSON 导出目前主要导出状态记录和行动事件，需要明确加入自己的漂流瓶和可见回应，并在删除后验证相关本机键已清理。

## 3. 截止日前的产品目标

### 3.1 必须证明的四件事

1. 用户可以低负担地完成一次记录，并知道自己处于示例档案、空白档案还是匿名记录。
2. 用户可以区分普通波动、数据不足和高风险三种路径，并说出至少两条判断依据。
3. 高风险时普通行动不能从首页、导航、深链接、按钮或直接调用层绕过；数据不足时不输出装作确定的普通建议。
4. 用户可以生成、编辑和复制一段最小披露求助表达，知道会分享什么、不会分享什么，且系统不自动发送或上报。

### 3.2 明确不作为截止目标

- 不做 AI 心理治疗、开放式危机陪聊或自动诊断。
- 不做真实多人漂流瓶、匿名社区、私信和社区运营后台。
- 不做学校个人风险名单、班级排名、宿舍热力图或自动预警名单。
- 不做生产级加密同步、设备丢失恢复和跨设备密钥系统。
- 不做 7/14 天基线、考试周/疾病/返乡等特殊时期模型。
- 不把合成数据写成真实用户结果，不把规则测试写成临床疗效证据。

## 4. 五天执行排程

日期按 2026-08-02 作为 Day 1 计算；如果实际截止日不同，只平移日期，不改变顺序和验收标准。

### Day 1：范围冻结、数据边界和入口盘点

**目标**：知道当前版本到底能证明什么，防止演示数据、匿名记录和空白档案混在一起。

**工程任务**

- 建立路由和动作入口清单：`/`、`/checkin`、`/insight`、`/companion`、`/help`、`/settings`、`/rules`、`/bottle`，以及首页按钮、底部导航、深链接和直接调用。
- 盘点每个入口在三种状态下的行为：普通波动、数据不足、高风险。
- 对所有演示标签统一使用“示例记录”“匿名记录”“空白档案”，禁止用“真实”“已验证”“临床”等模糊字样。
- 从清空本机数据后的空白档案开始，保存一份基线行为结果。
- 建立三个固定测试 Fixture：
  - `NORMAL_DEMO`：只用于演示个人节奏和依据。
  - `INSUFFICIENT_EMPTY`：缺少必要信号，只允许补充记录。
  - `HIGH_RISK_TEXT`：只保留求助入口。

**产品/UX 任务**

- 冻结首页主叙事为“当前状态 → 判断依据 → 下一步”。
- 将 RISE 数字降为辅助信息，不再用数字作为第一句产品价值。
- 漂流瓶入口标注为“匿名漂流瓶 · Demo”，不放入主要答辩开场。

**当天交付物**

- `docs/心晴下一步执行计划_2026-08-02.md`
- `docs/演示数据与状态矩阵_2026-08-02.md`
- 入口清单和三态行为矩阵
- Day 1 基线测试结果

**完成标准**

- 从清空档案重新打开应用时，页面明确显示“空白档案”或“还没有记录”。
- 演示记录、匿名手动记录、漂流瓶本机数据有明确标签和独立清理边界。
- 所有人可以根据矩阵回答：这个状态能做什么、不能做什么、为什么。

### Day 2：Safety Gate 全入口和三态演示

**目标**：把竞品报告中最能防守的差异“Policy-as-Product”做成可验证的工程合同。

**工程任务**

- 将普通动作入口统一经过 `canStartAction` 或等价调用层。
- 将 `/bottle` 也纳入状态门控：高风险和数据不足不能进入普通互动 Demo；普通波动才允许进入。
- 检查首页主按钮、底部导航、陪伴、规则实验室、深链接、直接函数调用和反馈学习。
- 建立三态矩阵：

| 状态 | allowedActions | 第一主按钮 | 明确阻断 |
|---|---|---|---|
| 普通波动 | 普通安全行动 | 开始第一步 | 无，仍受调用层校验 |
| 数据不足 | `checkin` | 补充一条记录 | 陪伴、漂流瓶、个性化普通建议 |
| 高风险 | `help` | 打开求助入口 | 陪伴、普通练习、自检、漂流瓶、反馈学习 |

- 扩充文本回归样本：直接表达、否定语境、引用他人、隐喻、错别字、多段文字、中英文混杂。

**产品/UX 任务**

- 三种状态都必须出现：当前状态、依据、允许的下一步、暂不建议的动作。
- “数据不足”不要显示伪精确分数；用“还不够了解”解释下一步。
- 高风险页面第一主按钮只能是求助表达或真实资源，不让普通练习抢占注意力。

**当天交付物**

- Safety Gate 三态规则矩阵
- `tests/safety-gate-matrix.js` 或等价回归测试
- 三种状态的截图和一段可复述解释

**完成标准**

- 高风险测试用例普通动作阻断率为 100%。
- 数据不足测试用例不进入陪伴、漂流瓶或普通行动。
- 首页、底部导航、直接 URL 和直接调用四类入口绕过数为 0。
- 每个决策至少带有 `decisionId`、`reasonCodes`、`evidence`、`policyVersion`、`dataSource` 和 `confidence`。

### Day 3：Privacy Receipt、Warm Handoff 和导出删除边界

**目标**：把“我们重视隐私”变成用户能看见、工程能断言的数据收据。

**工程任务**

- 扩展 `HelpDraftEvent`，最少增加：
  - `decisionId`
  - `includedFields`
  - `excludedFields`
  - `sourceTypes`
  - `userEdited`
  - `copiedAt`
- `HelpComposer` 在生成、编辑、勾选状态摘要、复制时记录收据；不保存用户编辑后的正文。
- 分享预览固定显示：
  - 会包含：用户编辑后的正文、主动勾选的状态摘要、选择的支持需求和紧迫程度。
  - 不会包含：原始备注、完整历史、匿名 ID、未选择的睡眠/步数/设备信息。
- 设置页导出 JSON 增加：
  - `bottles`：当前匿名档案自己的瓶子。
  - `bottleReplies`：自己瓶子的可见匿名回应。
  - `dataMode` 和导出边界说明。
  - `privacyReceiptEvents` 或等价匿名收据事件。
- 删除本机记录时同步清理漂流瓶、回应、隐藏和举报相关键；导出的文件不承诺会被自动删除。
- 对热线、校园链接和超过核验窗口的资源保持失效兜底，失效资源不能渲染成可用主按钮。

**产品/UX 任务**

- 将“分享前确认”做成真正的收据模块，而不是一段说明文字。
- 让用户在 60 秒内完成：选择对象 → 选择需要 → 选择紧迫度 → 编辑 → 预览 → 复制。
- 高风险默认“现在需要联系”，普通路径默认不强迫即时联系。

**当天交付物**

- Privacy Receipt 字段定义
- 求助桥测试清单
- 导出 JSON 示例
- 删除前后本机键清单

**完成标准**

- 未勾选状态摘要时，复制正文不含状态摘要。
- 原始危机词、原始备注和完整历史不进入默认草稿。
- 测试可以证明复制前没有外部发送请求。
- 导出的 `dataMode` 能区分示例、匿名和空白档案。
- 删除后重新打开不能看到自己之前的记录或漂流瓶。

### Day 4：用户理解度走查、专业审核和答辩证据

**目标**：验证用户理解的是“下一步和依据”，而不是只记住一个分数。

**走查对象**

- 至少 3 名内部成员或目标用户做认知走查；如果能找到专业审核者，优先邀请心理中心老师、辅导员或相关专业人士。
- 不要求参与者输入真实危机经历；只使用固定的合成高风险场景。
- 参与者出现真实高风险表达时停止产品任务，按既定人工转接流程处理，不继续收集研究数据。

**六个走查任务**

1. 从空白档案完成一次低负担记录，记录耗时和主观负担。
2. 用自己的话解释当前状态以及至少两条判断依据。
3. 指出当前允许的动作和暂不建议的动作。
4. 比较普通波动、数据不足、高风险三张状态卡，指出三者下一步差异。
5. 生成并编辑一段发给朋友、老师或家人的求助草稿。
6. 指出哪些内容会离开本机、哪些内容不会被带出。

**要收集的指标**

| 假设 | 记录指标 | 暂不宣称 |
|---|---|---|
| 记录负担可接受 | 完成时间、放弃点、主观负担 | 临床依从性 |
| 用户理解个人节奏 | 能否说出 2 条依据 | 诊断准确性 |
| 用户理解 Gate | 能否区分三态下一步 | 危机预测能力 |
| 求助桥降低表达成本 | 草稿完成时间、自然度、愿意使用程度 | 实际危机处置效果 |
| 隐私收据清楚 | 能否识别包含/不包含字段 | 绝对隐私安全 |

**答辩证据包**

- 1 页：竞品共同能力与心晴空位
- 1 页：记录 → 基线 → Gate → 下一步 → Warm Handoff 闭环
- 1 页：普通波动、数据不足、高风险三态矩阵
- 1 页：Privacy Receipt 示例
- 1 页：测试结果和 0 绕过结论
- 1 页：已完成、截止日后、明确禁止的范围
- 8-10 分钟演示脚本和备用录屏

**完成标准**

- 参与者不只复述分数，能说出下一步和至少两条依据。
- 参与者能说出至少两项默认不会分享的内容。
- 专业审核意见被记录为“通过、需要修订或暂缓”，不口头留存。
- 演示材料区分合成数据、匿名试用数据和公开竞品资料。

### Day 5：全量回归、备份和冻结

**目标**：把可演示版本变成可交付版本，不在最后一天增加新功能。

**必须执行的回归**

```text
npm.cmd run typecheck
npm.cmd run test:domain
npm.cmd run test:react:shell
npm.cmd run test:react:ui
npm.cmd run test:react:security
npm.cmd run test:react:storage
npm.cmd run test:react:bottle
npm.cmd run test:react:visual
npm.cmd run build
```

**从空白档案重新走的路径**

1. 空白档案：数据不足 → 补充记录，不进入普通行动。
2. 普通波动：个人节奏 → 查看依据 → 完成一个安全行动 → 反馈。
3. 高风险：记录高风险文本 → 只进求助 → 生成最小披露草稿 → 预览 → 复制。
4. 漂流瓶：低风险进入 → 投放/捞取/回应 → 导出 → 删除 → 确认本机清空。

**备份动作**

- 复制当前源码和 `dist` 到带日期的冻结目录。
- 备份 `docs/` 中的竞品报告、执行计划、演示脚本、规则矩阵和截图。
- 保存一次通过回归的命令输出。
- 生成一个只读交付压缩包；压缩包中明确标注“不代表生产级加密存储”。
- 记录版本号、构建时间、测试时间和当前未完成项。

**冻结规则**

- Day 5 后只修复阻断演示、违反安全边界或导致构建失败的问题。
- 不新增 AI、社区、学校后台、复杂图表、营销页面和未验证的资源。
- 所有未完成项写入“截止日后路线”，不以 TODO 形式隐性留在主流程里。

## 9. 截止日后的路线

### 0-30 天：把差异做成稳定产品

- 完成全入口安全审计和危机文本回归集。
- 完成 1 个学校/校区的资源配置模板和责任人核验流程。
- 增加行动难度、再次尝试意愿和个人行动记忆。
- 让判断收据和分享收据可撤回、可导出、可审查。
- 邀请至少 1-2 名专业审核者，记录修订意见。

### 31-60 天：做真实用户理解度验证

- 招募 10-20 名大学生，连续 3-5 天匿名试用。
- 只验证记录负担、三态理解、判断依据、求助表达和隐私理解。
- 不收集真实危机经历，不将试用数据写成临床证据。
- 达到建议门槛后才进入下一阶段：三态区分 80%、能说出两条依据 80%、求助草稿 2 分钟内完成 70%、分享字段识别 80%。

### 61-90 天：形成校园复制包

- 7/14 天个人基线窗口。
- 考试周、返乡、疾病、旅行等特殊时期标记。
- 单校资源配置、核验记录、策略版本和审核记录三件套。
- 加密存储、设备丢失、备份恢复、导出文件和删除验证设计。
- 评估真实校园合作，但不做个人风险看板。

### 长期禁止作为主线

- AI 心理治疗和开放式危机陪聊。
- 学校个人风险监控、排名、预警名单。
- 未治理的真实匿名社区和危机社区。
- 自动联系、自动报警、自动上报。
- “降低焦虑/抑郁”“预测危机”“证明疗效”等未经证据支持的宣传。

## 10. 8-10 分钟演示脚本

### 0:00-1:00 先说竞品空位

“市场上已经有很多产品负责记录、内容、AI 对话和真人连接。心晴不复制其中一个类别，而是处理用户发现状态不对之后的中间问题：我是否偏离了自己、现在能做什么、是否需要找人、应该怎么说。”

### 1:00-3:00 普通波动

- 展示个人节奏和状态语义。
- 点击“看依据”。
- 指出睡眠、活动、连接感和个人历史的关系。
- 展示当前允许的最小行动。
- 强调这不是诊断，也不是疗效证明。

### 3:00-4:30 数据不足

- 从空白档案进入记录。
- 只填写部分信号。
- 展示“还不够了解”。
- 说明系统拒绝装作给出精确结论，下一步是补充记录。

### 4:30-6:30 高风险

- 使用固定合成文本，不要求任何人输入真实危机经历。
- 展示普通行动被暂停。
- 打开求助页，展示资源核验状态和“联系真实的人”。
- 说明任何普通入口都无法绕过 Safety Gate。

### 6:30-8:00 Warm Handoff 与 Privacy Receipt

- 选择朋友/老师/家人。
- 选择“先听我说、陪我保持联系、陪我找支持”。
- 选择紧迫程度。
- 编辑草稿。
- 展示会包含和不会包含的字段。
- 复制前强调系统不会自动发送、自动报警或自动上报。

### 8:00-9:00 数据控制

- 打开设置查看数据来源。
- 导出 JSON，指出示例、匿名记录和漂流瓶边界。
- 删除本机数据，重新打开确认应用内不可见。

### 9:00-10:00 说明暂缓项

“真实多人社区、校园个人风险监控、AI 治疗和生产级云同步没有被藏在 Demo 里。它们需要独立的治理、专业审核和隐私设计，属于截止日后的决策门。”
