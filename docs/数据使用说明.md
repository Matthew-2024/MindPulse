# 心晴 MindPulse 数据使用说明

本文档用于区分三类数据，避免国赛答辩中把“合成演示数据”“公开数据验证”和“真实用户研究”混在一起。

## 1. 合成演示数据

| 文件 | 用途 | 是否可作为真实用户研究 |
|---|---|---|
| `data/synthetic-mindpulse-30-records.json` | 喂给恢复指数、风险分级、推荐路径规则，验证系统链路 | 不可以 |
| `data/synthetic-mindpulse-30-analysis.json` | 由脚本生成的规则分析结果 | 不可以 |

合成数据只能用于演示、测试和答辩中的“规则链路验证”。在 PPT 或论文中必须标注为“合成演示数据”，不能写成真实试用数据。

运行方式：

```bash
node tools/analyze-synthetic-records.js
```

或：

```bash
npm run analyze:synthetic
```

当前分析结果摘要：

| 指标 | 结果 |
|---|---|
| 记录数 | 30 |
| 平均恢复指数 | 73 |
| 风险分布 | 稳定观察 11、普通波动 6、中度关注 12、高风险 1 |

## 2. 公开数据集验证

建议使用 Dartmouth StudentLife Dataset 作为公开数据验证来源。该数据集来自 48 名 Dartmouth 学生、10 周手机感知与自报告数据，包含睡眠、活动、压力、情绪、社交、心理量表等信息，适合说明作品选题和多信号融合方向的合理性。

使用边界：

| 可以做 | 不应做 |
|---|---|
| 说明大学生压力、睡眠、活动、社交之间确实存在长期关联 | 把公开数据说成本校用户数据 |
| 把公开数据作为算法验证或文献支撑 | 把公开数据直接说成产品上线数据 |
| 引用数据集说明作品方向有研究基础 | 声称作品已经在该数据集上训练出医学模型 |

推荐答辩说法：

> 我们用合成演示数据验证规则链路，用公开 StudentLife 数据集作为选题与多信号融合的外部参考；真正的产品有效性仍需要本校匿名试用和专业审核来验证。

## 3. 真实用户研究

国赛最有说服力的数据仍然是团队自己采集的匿名试用数据。

真实匿名试用证据统一回填到 `docs/user-study-evidence/`。在该目录补齐 `trial-summary.md`、`participant-ledger.csv`、`feedback-quotes.md`、`consent-script.md` 和 `risk-events.md` 前，不得把 A07 写成“通过”或“已完成真实用户研究”。

最低要求：

| 项目 | 要求 |
|---|---|
| 人数 | 10-20 名大学生 |
| 周期 | 3-5 天 |
| 数据 | 记录完成率、干预完成率、可用性评分、主观反馈 |
| 伦理 | 匿名、知情、自愿、可退出、不收集敏感身份信息 |
| 审核 | 最好由心理中心老师或辅导员审核问卷和风险流程 |

国赛材料中三类数据应这样命名：

| 数据类别 | 推荐命名 |
|---|---|
| 编写的 30 条记录 | 合成演示数据 |
| 网上公开数据 | 公开数据集验证 |
| 自己找同学试用 | 匿名用户试用数据 |

专业审核证据统一回填到 `docs/professional-review-evidence/`。在该目录补齐 `review-summary.md`、`review-issues.csv`、`material-version.md`、`fix-log.md` 和 `permission-note.md` 前，不得把 A08 写成“通过”或“已完成专业审核”。

## 4. Supabase 云端同步数据边界

当前新增的是“邮箱验证码 + 加密同步”工程模板，不等同于已经完成正式线上试点。正式部署前，需要在 Supabase 项目中配置邮件服务、环境变量、允许域名和安全审查。

数据分层：

| 层 | 保存内容 | 不保存内容 |
|---|---|---|
| `accounts` | `account_id`、`email_hash`、邮箱验证时间、创建时间 | 心理文本、日记、评估内容 |
| `email_verifications` | `email_hash`、`code_hash`、过期时间、尝试次数 | 明文验证码 |
| `devices` / `sessions` | 设备 ID、设备名、会话 hash、过期和撤销状态 | 明文密码、心理文本 |
| `vaults` | 随机 `vault_id` 与账号的同步授权关系 | 明文记录内容 |
| `encrypted_items` | `vault_id`、`ciphertext`、`nonce`、`salt`、算法和更新时间 | 明文标题、明文标签、明文摘要、明文心理文本 |

关键边界：

- 注册后不会默认上传心理文本。
- 用户需要手动开启“加密同步”。
- Web 原型先在本地用 WebCrypto 加密，再上传密文 blob。
- 服务端 `mindpulse-api/sync-vault` 动作会拒绝包含 `records`、`note` 或 `plaintext` 的请求。
- 邮箱只用于账号验证与设备管理，心理文本归属 `vault_id`，不直接挂在邮箱下面。

推荐答辩说法：

> Supabase 只负责邮箱验证码、设备管理、同步授权和密文存储。心理文本默认在本地，开启同步后也先在本地加密，云端只看到 `vault_id` 和 `encrypted_items.ciphertext`。
