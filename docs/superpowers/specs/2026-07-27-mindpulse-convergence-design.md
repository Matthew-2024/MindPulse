# 心晴 MindPulse 收口式创新改造设计

## 1. 目标与范围

本次改造以现有 `心晴MindPulse_Web原型.html` 为唯一 Web 开发主线，不迁移 React，不推倒现有页面，不改变产品现有的手机画布比例和视觉模板。产品主线统一为：发现个人节奏偏移，判断当前策略允许的下一步，并在需要时帮助用户向真人求助。

改造覆盖：产品文案、首页信息层级、可审计决策模型、Safety Gate、匿名漂流瓶、安全约束下的个性化、三状态规则演示、备忘录、待办日程和 iOS 尺寸网页验收。

不新增：AI 聊天、虚拟宠物、积分、内容库、自动上报、群体排名、真实 HealthKit 或未经验证的医学模型。

## 2. 不可破坏的 UI 约束

以下要求是硬性验收条件：

- 保留现有 iOS 风格、柔和绿橙配色、卡片圆角、阴影、字体层级和留白节奏。
- 主设计画布改为 iPhone 14 Pro 竖屏 CSS 视口：393 x 852；设备像素参考为 1179 x 2556（3 倍缩放）。
- 在大于 393 px 的浏览器、平板和桌面视口中，应用保持 393 px 宽并水平居中，不扩展为桌面仪表盘；在小于 393 px 的视口中，画布宽度使用 100vw 自适应收缩。
- 保留现有页面视觉比例、顶部导航层级、底部导航结构和中心记录按钮的相对尺寸；只做适配 393 x 852 所需的等比例微调。
- 新增页面复用现有 `page`、`nb`、`page-body`、`status-card`、`quiet-card`、`setting-card`、`btn`、`btn-lite`、`field` 等视觉语言。
- 不全局修改现有基础字号、卡片内边距、圆角和按钮高度；新增样式只使用局部类名。
- 393 x 852 是主要设计和截图验收视口，不出现横向滚动、底部导航遮挡、按钮溢出或文本截断。
- 375 x 667 作为小屏兼容视口，允许内容纵向滚动，但不得压缩卡片到不可读或改变整体视觉比例。
- 430 x 932 与 1024 x 768 中应用保持 393 px 手机画布居中，不拉伸卡片、字号、按钮或底部导航。
- 顶部使用 `env(safe-area-inset-top)`，底部内容和导航使用 `env(safe-area-inset-bottom)`，兼容灵动岛区域和 Home Indicator。
- 所有主要触控目标不小于 44 px；键盘焦点可见；支持 `prefers-reduced-motion`。
- 不使用外部字体、远程图片或外部 API。

视觉回归以当前页面截图为基准。允许的信息变化仅限文案、首页模块顺序和新增功能入口；不允许主题重做或比例漂移。

## 3. 架构方案

采用“保留单 HTML 入口 + 新增可测试纯 JavaScript 模块”的方案。

- `心晴MindPulse_Web原型.html`：继续负责应用状态、页面渲染和现有交互，是可直接打开的主入口。
- `src/domain/decision-policy.js`：固定 Reason Code、`DecisionTrace`、数据完整度、风险模式、允许/阻断动作和 Safety Gate 契约。
- `src/features/memo/memo-model.js`：笔记、事项、自动编号、插入、删除、搜索和联想词扩展。
- `src/features/schedule/schedule-model.js`：待办日程、日期范围、周/月/年视图数据和截止时间排序。
- `src/features/bottle/bottle-repository.js`：本地演示漂流瓶仓储接口；未来后端实现保持相同方法签名。
- `tests/`：新增领域、备忘录、日程、漂流瓶和页面安全路径测试。

模块使用浏览器与 Node 均可加载的无依赖导出方式，避免构建工具和网络依赖。HTML 在模块加载失败时不得绕过 Safety Gate；安全策略模块不可用时采用保守降级，只允许补充记录或求助。

## 4. 首页与产品叙事

首页首屏按以下顺序组织：

1. 今天偏离了什么。
2. 睡眠、活动、连接和情绪的当前值、个人基线与偏移量。
3. 数据来源、完整度和置信度；数据不足时显示“基线建立中”。
4. 当前安全策略。
5. 当前策略允许的下一步。
6. 判断证据与决策编号。

恢复指数继续保留，但缩小为辅助指标，不再作为首屏最大视觉元素。主按钮按策略切换：

- 数据不足：补充一条记录。
- 普通波动：查看这一步为什么适合你。
- 中度关注：连接一个可信任的人。
- 高风险：进入求助入口。

首页新增两个紧凑入口：“备忘录”和“待办日程”。入口沿用现有卡片结构，不挤压首屏核心策略判断；在 iPhone 14 Pro 的 393 x 852 主视口中保持现有卡片和导航比例，在 375 x 667 的较短视口中允许向下滚动。

统一文案：

- “推荐动作”改为“当前策略允许的下一步”。
- “健康评分”或泛化分数表达改为“本次记录指数”。
- “情绪异常”改为“个人节奏偏移”。
- “心理干预”改为“低负担行动”。
- “风险预测”改为“安全策略判断”。

## 5. 可审计决策模型

固定 Reason Code：

```text
DATA_INSUFFICIENT
BASELINE_DEVIATION
LOW_SLEEP_REPEATED
LOW_CONNECTION_REPEATED
NEGATIVE_MOOD_REPEATED
TEXT_CRISIS_SIGNAL
SINGLE_WAVE
STABLE_BASELINE
```

每次评估返回：

```text
decisionId
evaluatedAt
reasonCodes
mode
allowedActions
blockedActions
evidence
policyVersion
dataSource
confidence
```

`decisionId` 在一次页面评估周期内稳定，保存新记录后重新生成。证据必须来自实际输入或历史记录，不使用空泛“模型判断”。数据来源限定为“自我记录”“设备记录”“合成演示”或其组合。

## 6. Safety Gate 安全契约

领域层、页面层和导航层执行同一契约：

- 高风险时 `allowedActions` 只能包含 `help`。
- 高风险时呼吸、散步、专注、记录、睡眠等普通行动全部进入 `blockedActions`。
- 高风险时 Companion 页面不渲染普通行动，并自动转入求助页。
- 直接调用普通行动完成命令时也必须拒绝，不能只依赖隐藏按钮。
- 数据不足时只允许补充记录。
- 高风险事件不写入个性化反馈学习。
- 策略模块异常时采用保守降级，不能默认开放普通行动。

底部导航保持现有尺寸与位置。高风险时不删除导航造成布局跳动，而是禁用不允许的入口，并把点击行为导向求助说明。

## 7. 匿名漂流瓶演示版

漂流瓶是本地演示功能，不伪装成真实多用户后端。

用户可以：

- 写下并投放匿名漂流瓶。
- 从本地演示瓶池随机捞取一条其他匿名瓶子。
- 对捞到的瓶子写回复。
- 查看自己投放的瓶子及收到的本地演示回复。

回复链仅在当前匿名档案中可见。界面标注“本机演示海域，尚未连接真实社区”。不展示手机号、学号、定位或实名信息；不自动代替用户联系任何人。

仓储接口固定为：

```text
listOwnBottles(profileId)
createBottle(profileId, content)
drawBottle(profileId)
replyToBottle(profileId, bottleId, content)
listRepliesForOwnBottle(profileId, bottleId)
```

当前实现使用 `localStorage` 与内置演示瓶池。未来接后端时只替换仓储实现，不改页面调用方式。

## 8. 安全约束下的个性化

- 普通安全反馈少于 3 次：个人倾向显示“仍在建立”，不调整推荐顺序。
- 普通安全反馈达到 3 次：允许根据平均反馈变化调整普通行动顺序。
- 高风险反馈永远不参与学习。
- Companion 与规则实验室显示倾向状态、有效反馈次数和已排除的高风险事件数。

一次偶然反馈不能形成稳定倾向。历史数据缺字段时按“仍在建立”处理，不推断为已形成。

## 9. 三状态答辩演示

规则实验室新增固定场景：

- `LAB-01` 数据不足：只允许补充记录。
- `LAB-02` 普通波动：允许低负担行动。
- `LAB-03` 高风险：只允许求助。

每次点击都实时调用同一个决策评估函数。页面展示策略、Reason Code、允许动作、阻断动作、证据、数据来源和置信度，并标注“合成演示场景，不代表真实用户数据”。

## 10. 备忘录

### 10.1 列表页

列表页参考用户提供的第一张图片，同时适配心晴现有视觉风格：

- 顶部显示“全部笔记”和笔记数量。
- 提供搜索框。
- 笔记以现有圆角卡片呈现标题、更新时间和首条事项摘要。
- 右下角提供新增笔记按钮，但尺寸、阴影和颜色与现有中心操作按钮协调。
- 点击卡片进入笔记详情。

### 10.2 详情页

详情页参考第二张图片：

- 顶部返回按钮、可编辑标题、更新时间和本地分类标签。
- 正文不是自由文本大段输入，而是一个可编辑事项列表。
- 每个事项左侧编号由列表顺序实时生成，不把编号保存进事项文本。
- 每项后提供插入、删除和移动操作；在任意中间位置插入后，后续编号自动连续重排。
- 新建事项默认追加到末尾；空事项失焦后自动清理，但至少保留一个可输入行。
- 删除笔记需二次确认。

示例：现有事项为 1、2、3，在第 2 项后插入新事项后，显示为 1、2、3、4；删除第 2 项后显示为 1、2、3，不出现重复或跳号。

### 10.3 搜索

搜索覆盖标题与所有事项。相关度顺序：

1. 标题直接包含。
2. 事项直接包含。
3. 同义词/联想词包含。
4. 中文字符重合度达到阈值。

内置可扩展同义词表，例如：

```text
竞赛 -> 比赛、赛事、国赛、答辩、参赛
作业 -> 课程、报告、论文、DDL、截止
运动 -> 健身、跑步、训练、锻炼
```

搜索结果展示命中原因；无结果时给出联想词建议。搜索全部在本机完成。

## 11. 待办日程

- 支持新增、编辑、完成和删除带日期的待办事项。
- 默认周视图，使用分段控件切换周、月、年。
- 日历日期显示当天事项数量和最多两条摘要，点击日期查看完整列表。
- 提供日期范围检索：今天、3 天内、8 天内、30 天内和自定义日期。
- 范围结果仅展示未完成事项，并按截止时间从近到远排序。
- 无截止时间事项单独放在结果末尾。
- 页面底部显示简短暖心话语，根据完成情况选择，不使用恐吓、命令或疗效承诺。

所有日历计算使用本地日期，避免 UTC 导致日期偏移。周视图以周一为起点。

## 12. 数据存储与迁移

新增数据按当前匿名档案隔离：

```text
mindpulse:<profileId>:memos
mindpulse:<profileId>:scheduleItems
mindpulse:<profileId>:bottles
mindpulse:<profileId>:bottleReplies
```

数据读取必须校验数组、ID、时间和字符串字段。损坏数据回退为空集合，不影响核心状态判断。现有档案无新增字段时自动初始化，不修改旧记录。

JSON 导出新增备忘录、日程、自己投放的漂流瓶和可见回复。删除当前档案或清除本地数据时同步删除新增键。

## 13. 错误处理与边界

- 空标题使用“未命名笔记”，不阻止保存事项。
- 纯空白事项不参与编号、摘要或搜索。
- 搜索输入进行长度限制和 HTML 转义。
- 日程结束日期早于开始日期时交换或提示，不产生负范围。
- 漂流瓶内容为空时不投放；连续点击不会重复创建。
- 本地存储写入失败时提示“本机存储空间不足或不可用”，保留当前编辑内容。
- 高风险策略判断优先于所有备忘录、日程、漂流瓶和普通行动入口。

## 14. 测试与验收

采用测试先行：每项新行为先写失败测试并确认失败，再实现最小代码。

领域测试：

- 八类 Reason Code 与决策追踪字段。
- 数据不足、高风险和保守降级策略。
- 高风险普通行动命令拒绝。
- 个性化 0、2、3 次反馈边界及高风险排除。

备忘录测试：

- 追加、任意位置插入、删除后的自动连续编号。
- 空事项不编号。
- 标题、事项、同义词和字符重合搜索。
- 不同匿名档案数据隔离。

日程测试：

- 周一开周、月/年数据分组。
- 8 天范围边界与截止时间排序。
- 日期本地化和无截止事项排序。

漂流瓶测试：

- 本地随机捞取不返回自己的瓶子。
- 回复仅对自己投放瓶子的当前档案可见。
- 仓储方法保持未来后端可替换接口。

UI 与安全测试：

- 首页信息顺序和策略按钮。
- 高风险不能进入 Companion 或执行普通行动。
- 三个 LAB 场景实时输出。
- 备忘录新增、编辑、插入、删除、搜索完整路径。
- 日程新增、周/月/年切换和 8 天检索。
- 393 x 852 主视口无横向滚动、遮挡和比例变化；页面关键操作在首屏或一次自然滚动范围内可达。
- 375 x 667 小屏兼容视口无横向滚动；430 x 932 与 1024 x 768 保持 393 px 手机画布居中且不拉伸。
- 键盘焦点、44 px 触控目标和 reduced-motion。

最终运行现有规则测试、合成数据分析、UI/安全/存储/视觉测试和 `preflight`。若浏览器测试依赖缺失，先补齐项目依赖再执行，不把“测试脚本存在”写成“测试通过”。

## 15. 成功标准

- 首页 5 秒内能看出“个人节奏偏移 + 当前安全策略 + 允许的下一步”。
- Safety Gate 在领域、导航和页面三层均不可绕过。
- 备忘录视觉接近参考图的信息结构，同时保持心晴原有尺寸、配色和卡片比例。
- 备忘录事项可中间插入并始终自动连续编号。
- “竞赛”能联想到含“比赛、国赛、答辩”等词的笔记。
- 日程默认周视图，8 天内检索按截止时间排序。
- 漂流瓶可完整演示，且明确不是已上线的真实多用户社区。
- 旧数据可继续读取，新增数据按匿名档案隔离。
- iPhone 14 Pro 的 393 x 852 作为 UI 大小和排版比例的设计基准；其他目标视口仅做居中或收缩适配，不改变该基准风格。
