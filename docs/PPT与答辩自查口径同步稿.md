# 心晴 MindPulse PPT 与答辩自查口径同步稿

本文档用于把 `docs/自我审查项目.md` 的可信与安全设计同步到国赛 PPT、答辩脚本和演示视频。它不是新的功能说明，而是展示材料的统一口径，避免把自我觉察说成诊断治疗、把合成演示数据说成真实用户研究。

## 1. 建议新增 PPT 页

页标题：

```text
可信与安全设计：先边界，再推荐
```

页面主句：

```text
心晴不是心理诊断产品，而是端侧、匿名、可解释、可审查的早期觉察与求助桥梁。
```

三栏内容：

| 栏目 | 放什么 | 推荐文案 |
|---|---|---|
| 产品边界 | 做什么 / 不做什么 | 做早期觉察、轻量行动、求助表达；不做诊断、不治疗、不替代咨询、不作为危机干预终点 |
| Safety Gate | 高风险主路径 | 高风险信号出现后，停止普通轻干预主路径，优先展示热线、老师、家人和可信任成人 |
| 证据区分 | 数据与验证 | 合成演示数据用于规则链路验证；公开数据用于方向参考；真实有效性待匿名试用和专业审核回填 |

页脚标注：

```text
当前证据：20 条规则/个性化用例通过 + UI 冒烟测试通过；真实用户研究与专业审核仍按执行包推进。
```

## 2. 30 秒答辩插入段

可放在“心理安全与隐私”部分：

```text
我们把自我审查做成了项目的一部分，而不是最后补一句免责声明。第一，所有材料统一说明心晴不做心理诊断、不替代咨询；第二，Safety Gate 的优先级高于普通推荐逻辑，高风险样本不会继续把呼吸、散步作为主按钮；第三，我们严格区分合成演示数据、公开数据参考和真实匿名试用数据。现在 20 条规则和 UI 冒烟测试已经通过，真实用户研究和专业审核会按执行包回填，不会把演示数据包装成真实结果。
```

## 3. 评委追问回答

| 评委问题 | 建议回答 |
|---|---|
| 你们怎么避免误导成心理诊断？ | 我们把恢复指数定义为状态观察指标，不叫医学量表，也不输出疾病名称。PPT、README、页面和答辩都统一说“不诊断、不治疗、不替代咨询”。 |
| 高风险时为什么不继续推荐呼吸练习？ | 因为高风险场景下心理安全优先级高于普通自助建议。Safety Gate 触发后，主路径是求助入口，呼吸、散步等普通轻干预不能作为第一按钮。 |
| 你们的数据是真实用户数据吗？ | 目前有三类数据：合成演示数据用于规则链路验证，公开数据集只做方向参考，真实匿名试用数据待 10-20 人试用后回填。我们不会把合成演示数据说成真实用户研究。 |
| 有没有专业老师审核？ | 已准备专业审核执行包，会请心理老师、辅导员或校心理中心老师重点审核风险词、求助文案和高风险流程。没有完成前，只能说“待审核”，不能说已经专业认证。 |
| 为什么不用大模型直接心理聊天？ | 心理健康场景更重视边界和可审查性。当前版本先用透明规则和 Safety Gate，避免黑盒模型输出越界建议；未来端侧模型也只能作为辅助线索。 |
| 如果用户不理解恢复指数怎么办？ | 首页详情会展示情绪、睡眠、活动、社交连接和干预反馈的分数拆解，也展示个人基线偏移和推荐依据。匿名试用会专门验证用户能否复述分数来源。 |

## 4. 图表与数据标注规范

| 场景 | 必须标注 | 禁止写法 |
|---|---|---|
| 30 条演示记录图表 | 合成演示数据，用于规则链路验证 | 真实用户数据、用户研究结果 |
| StudentLife 或公开论文数据 | 公开数据集参考，用于说明方向合理性 | 本校采集数据、产品上线数据 |
| 后续匿名试用统计 | 匿名用户试用数据，说明人数、周期、指标 | 临床验证、疗效证明 |
| 规则测试截图 | 自动化规则测试结果，只证明当前规则可复现 | 证明心理疾病识别准确 |

## 5. PPT 禁用说法

| 不要说 | 改成 |
|---|---|
| 诊断抑郁症 / 诊断焦虑症 | 识别高风险信号，辅助早期觉察 |
| 治疗焦虑 / 治疗低落 | 提供低负担行动建议 |
| AI 心理医生 | 求助桥梁 / 状态观察工具 |
| 医学量表结果 | 轻自查分数提示 |
| 真实用户研究已经证明有效 | 匿名试用计划已准备，真实结果待回填 |
| 专业认证 / 临床有效 | 专业审核待执行，意见将按 P0/P1/P2 回填 |
| 高风险也可以先呼吸放松 | 高风险优先求助，普通练习不作为主路径 |

## 6. 演示视频旁白补充

可放在视频结尾 10 秒：

```text
所有演示数据均标注为合成演示数据，只用于验证规则链路。真实用户研究和专业审核不会被提前包装成结果。心晴的目标不是诊断或治疗，而是在状态变坏之前，帮助学生看见、行动，并把求助说出口。
```

## 7. 提交前检查

| 检查项 | 通过条件 |
|---|---|
| PPT 是否有可信与安全设计页 | 至少出现产品边界、Safety Gate、数据区分 |
| 答辩脚本是否说清楚自我审查 | 至少说明不诊断、Safety Gate 优先、三类数据区分 |
| 所有图表是否标注数据来源 | 合成演示数据、公开数据集参考、匿名试用数据三类不混用 |
| 是否仍写“待执行” | 没有真实试用和专业审核前，不写“已完成真实用户研究/专业审核” |
| 是否跑过验证 | 提交前运行 `npm.cmd run verify`，并保留输出截图 |
