# 心晴 MindPulse 国赛落地修改清单

本文档用于把作品从“高保真 Web 原型”推进到“可运行、可解释、可验证、有心理安全边界的国赛作品”。所有条目按评委最可能追问的顺序排列。

## 1. 必须先统一的技术口径

| 项目 | 当前状态 | 国赛要求 | 验收方式 |
|---|---|---|---|
| 恢复指数公式 | 已统一到规则引擎，页面不再使用 34-94 人工钳制 | 页面展示分数、导出数据、规则测试使用同一套公式 | 首页恢复指数与 `calculateRecoveryScore` 输出一致 |
| 风险分级 | 已从简单关键词扩展为危机模式 + 安全短语过滤 | 能说明误判控制、漏判边界和高风险处理流程 | `node tests/run-rule-tests.js` 通过误判与危机场景 |
| 推荐路径 | 已从单纯情绪映射升级为情绪 + 睡眠 + 社交 + 精力 | 能回答“为什么这次推荐这一步” | 测试覆盖低睡眠、低社交、疲惫、高风险 |
| 页面与规则模块 | HTML 已接入 `src/rules/browser-engine.js` | 演示页面不再维护另一套独立判断逻辑 | 首页、记录反馈、导出数据口径一致 |
| 高风险主路径 | 已改为 `help` 求助入口 | 不继续把普通轻干预作为主路径 | 高风险时按钮进入求助页 |

## 2. 代码层继续补强

| 优先级 | 修改项 | 具体做法 | 评委价值 |
|---|---|---|---|
| P0 | 增加 UI 行为测试 | 验证高风险输入后页面按钮进入求助页，不进入呼吸/散步等普通干预 | 证明“心理安全优先级”不是口号 |
| P0 | 扩充规则测试到 20 条以上 | 已扩展到 20 条，覆盖空文本、边界睡眠、误判短语、孤立表达、社交断联和连续负面状态 | 提升技术实现可信度 |
| P1 | 把 `browser-engine.js` 与 ESM 规则进一步合并 | 后续可用构建脚本生成浏览器版，避免长期双维护 | 提升工程规范性 |
| P1 | 补充真实数据输入模式 | 允许用户手动填写真实睡眠、步数，而不是只用演示映射 | 回答“数据从哪里来” |
| P2 | 增加端侧文本线索解释 | 从备注中提取压力源关键词，如考试、ddl、宿舍、失眠 | 强化“计算机设计”技术含量 |

## 3. 必须补齐的证据链

| 材料 | 最低要求 | 推荐呈现 |
|---|---|---|
| 用户研究报告 | 10-20 名大学生，连续试用 3-5 天 | 先按 `docs/匿名试用执行包.md` 执行，再按 `docs/user-study-evidence/README.md` 补齐 trial-summary、participant-ledger、feedback-quotes、consent-script 和 risk-events |
| 专业审核意见 | 1-2 名心理中心老师、辅导员或相关老师审核 | 先按 `docs/专业审核执行包.md` 审核风险词、求助文案、高风险转接流程，再按 `docs/professional-review-evidence/README.md` 补齐 review-summary、review-issues、material-version、fix-log 和 permission-note |
| 测试报告 | 展示规则测试、边界测试、误判测试结果 | 使用 `docs/当前测试与自查报告.md` 和 `docs/测试报告.docx`，附测试用例表和通过截图 |
| 自查截图证据 | 首页依据、高风险求助、规则实验室、设置证据板 | 运行 `npm.cmd run capture:evidence` 生成 `docs/review-evidence/` |
| 演示视频 | 3 分钟以内，真实操作录屏 | 按 `docs/演示视频录制脚本.md` 录制；录制前运行 `npm.cmd run demo:smoke`，覆盖记录、指数、解释、干预、高风险求助、导出和规则证据 |
| PPT | 10-12 页 | 问题、方案、技术、验证、安全、演示、规划；可信与安全设计页按 `docs/PPT与答辩自查口径同步稿.md` 同步 |
| 提交包 | 源码、原型、文档、视频、截图 | 文件命名统一，入口清楚 |

## 4. 用户研究执行模板

| 指标 | 记录方式 | 合格线 |
|---|---|---|
| 记录完成率 | 试用期间实际记录次数 / 预期记录次数 | 60% 以上 |
| 干预完成率 | 推荐后至少完成一步的人数比例 | 40% 以上 |
| 求助表达有用度 | 1-5 分主观评分 | 平均 3.8 以上 |
| 恢复指数理解度 | 用户是否能复述分数来源 | 70% 用户能理解 |
| 继续使用意愿 | 1-5 分主观评分 | 平均 3.5 以上 |

访谈问题建议：

| 问题 | 目的 |
|---|---|
| 你是否愿意每天用 1 分钟记录状态？ | 验证记录负担 |
| 恢复指数的分数拆解是否容易理解？ | 验证可解释性 |
| 推荐的第一步是否真的能做？ | 验证轻干预可执行性 |
| 求助表达文案是否像你会发出去的话？ | 验证求助入口价值 |
| 哪些内容会让你担心隐私？ | 验证隐私设计 |

## 5. 专业审核要问的问题

| 审核点 | 需要老师确认 |
|---|---|
| 风险词是否覆盖基本危机场景 | 当前词表是否需要增加或删减 |
| 安全短语过滤是否合理 | 哪些语句不应被直接判为高风险 |
| 高风险页面文案是否合适 | 是否避免刺激性、命令式、诊断式表达 |
| 求助转接是否充分 | 是否应加入校心理中心、辅导员、家人、热线 |
| 产品边界是否清楚 | 是否明确不诊断、不治疗、不替代咨询 |

## 6. 答辩必须统一的说法

| 评委问题 | 建议回答 |
|---|---|
| 这是心理诊断工具吗？ | 不是。恢复指数不是医学量表，只是基于情绪、睡眠、活动、社交和干预完成情况的可解释状态指标。 |
| 高风险怎么处理？ | 高风险信号出现后，系统停止普通自助建议，把求助入口、热线、老师、家人和可信任成人放到第一优先级。 |
| 为什么不用黑盒 AI？ | 心理健康场景更重视可解释和安全边界。当前版本先用透明规则，未来再考虑端侧模型作为辅助线索。 |
| 数据从哪里来？ | 当前 Web 原型支持用户自评和演示数据，下一阶段会加入真实睡眠、步数输入或移动端健康数据授权。 |
| 和普通情绪日记有什么区别？ | 心晴不仅记录情绪，还把状态变化、可解释分数、轻干预路径和求助表达连成闭环。 |
