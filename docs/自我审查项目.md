# 心晴 MindPulse 自我审查项目

本文档用于在国赛提交、用户试用和现场演示前，对心晴 MindPulse 进行内部自我审查。审查重点不是证明作品“没有问题”，而是持续发现夸大表达、心理安全、数据伦理、算法解释和演示证据中的风险，并把每个风险落实到修改记录。

## 1. 审查目标

心晴的自我审查目标是：确保项目始终被定位为面向大学生压力早期觉察、轻量行动和求助表达的端侧辅助工具，而不是心理诊断、医学量表、治疗方案或危机干预终点。

自我审查需要回答四个问题：

1. 作品有没有把“自我觉察”说成“诊断治疗”？
2. 高风险场景是否优先进入求助入口，而不是继续推荐普通轻干预？
3. 数据、算法、测试和用户研究是否被真实、清楚地区分？
4. 用户是否能理解系统为什么给出恢复指数、风险等级和行动建议？

## 2. 审查范围

| 审查维度 | 审查内容 | 最低通过标准 |
|---|---|---|
| 产品定位 | README、PPT、答辩稿、页面文案是否明确不诊断、不治疗 | 不出现“诊断抑郁症”“治疗焦虑”等医学化承诺 |
| 心理安全 | Safety Gate、求助页、高风险文案、热线与可信任成人提示 | 高风险样本不进入普通自助建议主路径 |
| 数据伦理 | 匿名档案、本地存储、导出、删除、用户研究说明 | 不收集手机号、学号、定位、联系人等非必要敏感信息 |
| 算法解释 | RISE 分数拆解、个人基线、风险证据、推荐依据 | 每个核心输出都能展示至少一条可解释依据 |
| 推荐边界 | 呼吸、散步、记录、联系朋友等轻干预建议 | 建议必须低负担、可退出，不承诺疗效 |
| 证据真实性 | 合成数据、公开数据、真实试用数据是否分开描述 | 不把合成演示数据包装成真实用户研究 |
| 前端演示 | 首页、记录、详情、求助、规则实验室、导出流程 | 现场路径可稳定复现，测试命令可运行 |
| 文档一致性 | README、国赛方案、数据说明、答辩脚本是否口径一致 | 已实现与规划中严格区分 |

## 3. 审查流程

| 阶段 | 触发时机 | 必做动作 | 产出 |
|---|---|---|---|
| 提交前审查 | 打包国赛材料前 | 跑测试、检查 README、检查 PPT 与答辩稿口径 | 自查记录、测试结果截图 |
| 试用前审查 | 开始 10-20 人匿名试用前 | 检查知情说明、退出机制、数据最小化、风险提示 | 试用说明、用户研究模板 |
| 高风险流程审查 | 修改风险词、求助页或推荐逻辑后 | 用高风险样本验证 Safety Gate 主路径 | 高风险流程截图、规则测试结果 |
| 展示材料审查 | 更新宣传页、路演稿或视频脚本后 | 删除夸大表达，补充边界说明 | 修改记录、最终材料版本 |
| 专业审核后复审 | 心理老师或辅导员给出意见后 | 把建议归类为 P0/P1/P2 并回填修改 | 专业审核纪要、整改清单 |

## 5. 风险分级与处理规则

| 等级 | 定义 | 处理要求 | 截止标准 |
|---|---|---|---|
| P0 | 可能造成心理安全、伦理或严重误导风险 | 立即停止提交或演示，先修复 | 修复后必须重新跑规则测试和 UI 冒烟测试 |
| P1 | 会影响评委信任、用户理解或数据真实性 | 提交前必须修复 | 修复后更新 README 或对应文档 |
| P2 | 表述不够精确、体验可优化、证据可增强 | 排入下一轮优化 | 记录到国赛落地清单 |

P0 示例：

- 页面或 PPT 声称可以诊断抑郁症、焦虑症或其他疾病。
- 高风险样本仍然把呼吸、散步等普通轻干预作为第一主按钮。
- 把合成演示数据写成真实用户试用数据。
- 收集手机号、学号、定位、联系人等与当前原型目标无关的敏感信息。
- 高风险文案使用刺激性、责备性或命令式表达。

## 7. 推荐答辩口径

> 心晴不是心理诊断产品，而是一个端侧、匿名、可解释、可审查的早期觉察与求助桥梁。我们把 Safety Gate 放在普通推荐逻辑之上，把合成演示数据、公开数据参考和真实用户研究严格区分，并通过自我审查清单持续检查文案、数据、规则和演示是否越界。
