# 心晴 MindPulse 竞品市场研究与创新策略报告

- 调研日期：2026-07-31
- 研究对象：心晴 MindPulse 当前 Web/iOS 原型及其拟服务的大学生早期心理状态觉察场景
- 研究范围：英文与中文市场的公开产品官网、帮助/隐私页、应用商店公开信息、教育政策与公开研究资料
- 研究目的：识别产品重叠能力，判断真正的差异化空间，给出可验证的创新优先级
- 证据口径：竞品官网自述只作为产品定位和功能证据；官网未展示的能力不写成市场绝对不存在；用户规模、评分和疗效表述均不作为独立的市场份额或临床证据

## 一、执行摘要

### 核心判断

心晴不应该继续把自己定义成“另一个情绪日记”“另一个 AI 陪伴”或“另一个匿名树洞”。这些方向已经有成熟产品和网络效应，单点功能很难形成优势。

心晴最有机会占据的位置是：

> 面向大学生的、学生拥有控制权的端侧早期觉察与求助转接层：先判断是否偏离自己的正常节奏，再解释当前能做什么、不能做什么，最后把求助表达交还给用户本人。

这不是“功能更多”的创新，而是解决一个成熟产品普遍没有把中间责任层做完整的问题：

```text
记录状态
  -> 判断数据是否足够
  -> 经过安全闸门
  -> 对比个人节奏而非群体平均
  -> 给出当前允许的下一步
  -> 必要时生成最小披露的求助草稿
  -> 记录用户对行动的主观反馈
```

### 最应该投入的三个创新方向

1. **Safety Gate 作为真正的策略执行层**：高风险时强制停止普通轻干预，数据不足时停止过度判断，所有行动入口都不能绕过策略层。
2. **校园 Warm Handoff 求助桥**：把“我可能需要帮助”转成“我能向谁、以什么语气、提出什么具体支持”，默认不带出原始日记，不自动上报和发送。
3. **个人节奏与最小披露隐私**：把 RISE 从一个数字升级为带置信度、缺失信号和特殊时期标记的个人观察工具，并让用户可以检查每次判断使用了什么数据、分享了什么数据。

### 不建议作为主创新的方向

- 泛化 AI 心理聊天
- 更多冥想、白噪音和睡眠音频
- 更多情绪标签、打卡、徽章和连续记录
- 公共匿名树洞或漂流瓶社区
- 面向学校的个人心理风险热力图
- 把 RISE 或风险等级包装成抑郁、焦虑等疾病诊断

这些方向要么已经高度同质化，要么需要内容规模、社区治理、临床证据或监管能力，和当前心晴的资源优势不匹配。

## 二、心晴当前基线

### 已经具备的产品能力

依据当前 README、页面组件、规则引擎和类型定义，心晴已经具备以下基础：

| 能力 | 当前实现 | 与市场的关系 |
|---|---|---|
| 低负担记录 | 情绪、睡眠、精力、步数、连接感、备注；支持每日多条记录 | 与 Daylio、Stoic、Bearable、MindDoc 直接重叠，不能单独作为创新 |
| RISE 恢复指数 | 情绪、睡眠、活动、社交连接、干预反馈的可解释拆解 | 有差异潜力，但不能称医学量表或疗效指标 |
| 个人基线 | 根据匿名档案历史记录判断是否偏离自己的节奏 | 是核心差异的基础，但需要更强的特殊时期和不确定性设计 |
| 风险分层 | 稳定观察、普通波动、中度关注、高风险、数据不足 | 竞品也有安全边界；差异在于是否成为可执行的策略门控 |
| Safety Gate | 高风险只允许求助；数据不足先补充记录；普通动作可被阻断 | 当前最值得继续深挖的工程与体验组合 |
| 轻干预推荐 | 呼吸、散步、专注、睡前放松、记录、联系朋友等 | 与 Tide、Headspace、Stoic、Wysa 等重叠；价值在于被安全策略允许后再推荐 |
| 反馈学习 | 记录行动前后主观变化，形成下一次推荐参考 | Bearable 的健康实验已有相邻能力；心晴需要强调个人反馈而非疗效因果 |
| 决策追踪 | Reason Code、证据、允许/阻断动作、策略版本、数据来源、置信度 | 目前最适合形成可审查差异的部分 |
| 求助表达 | 朋友、老师/辅导员、家人等对象的可编辑草稿 | 直接连接真实支持，比再做一个聊天机器人更有价值 |
| 校园资源配置 | 热线、心理中心、老师、链接、服务时间、最近核验日期 | 已有基础，下一步应升级为可验证、可过期提醒的资源目录 |
| 日报/周报 | 时间线、情绪趋势、低睡眠日、干预覆盖、Safety Gate 触发 | 常见功能，需和个人基线、决策依据绑定 |
| 隐私与数据控制 | 匿名档案、IndexedDB、本地优先、导出、删除、数据台账 | 方向正确，但 IndexedDB 本身不等于加密；生产版需补充加密、密钥、备份和设备丢失设计 |
| 漂流瓶 | 当前为本机演示海域，非真实多用户社区 | 不应作为主战场；真实上线需单独承担审核、举报、危机升级和未成年人保护 |

### 当前必须保持的产品边界

- RISE 是可解释的状态观察指标，不是抑郁、焦虑或其他疾病的诊断结果。
- 规则测试通过只证明规则可复现，不证明心理问题识别准确，也不证明治疗效果。
- 合成演示数据、公开数据参考、真实匿名试用数据必须分开标注。
- 当前原型的本地优先不等于绝对安全，不能把 `localStorage` 或 IndexedDB 说成加密保险箱。
- 高风险时不应继续把呼吸、散步等普通动作作为第一主按钮，求助连接必须保持优先级。

## 三、市场结构：用户真正可以替代心晴的产品

心晴面对的不是一个竞品类别，而是五类替代方案。它们争夺的是同一个用户时刻：用户发现自己状态不对，却还没有决定下一步怎么办。

| 市场路线 | 代表产品 | 用户购买的核心价值 | 心晴不应硬拼的地方 |
|---|---|---|---|
| 情绪记录与模式发现 | Daylio、Stoic、Bearable、MindDoc | 低成本记录、趋势、相关性、长期回顾 | 记录速度、图表数量、内容量、习惯激励 |
| AI 情绪陪伴 | Wysa、Youper、Headspace Ebb、7 Cups Noni | 随时对话、反思、练习、转介 | 对话自然度、模型规模、品牌和内容库 |
| 睡眠、冥想与专注 | Tide、Headspace、Stoic | 音频、呼吸、睡眠、专注计时 | 音频内容规模、审美和订阅习惯 |
| 同伴、社区与专业服务 | 7 Cups、壹心理、简单心理、心岛日记 | 倾听、树洞、社区、咨询师、课程 | 真人网络、社区活跃度、咨询服务和平台运营 |
| 校园心理健康体系 | 学校心理中心、辅导员、热线、校内树洞 | 监测预警、咨询、干预、转介 | 学校资源和处置能力；心晴应做学生自主进入这些资源前的桥梁 |

### 市场饱和度判断

| 能力 | 市场成熟度 | 对心晴的结论 |
|---|---:|---|
| 情绪/状态记录 | 很高 | 只做够用的入口，不能成为产品主叙事 |
| 趋势、相关性、周报 | 很高 | 作为解释证据，不要把图表数量当创新 |
| 多信号追踪 | 高 | Bearable 已证明成熟，心晴要强调个人基线和动作门控 |
| 习惯、打卡、徽章 | 很高 | 不适合在心理安全产品里作为主增长机制 |
| 呼吸、冥想、睡眠音频 | 很高 | 作为可插拔资源，不承担内容竞争 |
| AI 情绪聊天 | 很高且快速变化 | 不建议进入主战场；模型会迅速同质化，风险成本高 |
| 匿名树洞/漂流瓶 | 高 | 需要网络效应和审核治理，当前演示保持边界即可 |
| 危机资源转介 | 已有成熟先例 | 不要宣称独有；要把它做成不可绕过、可审计的策略执行 |
| 个人基线 | 中高 | 单点不独家，但和风险门控、行动反馈组合后有机会形成清晰定位 |
| 求助表达转译 | 中 | 7 Cups 等提供支持网络，心晴可专注于降低第一次开口成本 |
| 校园资源配置与过期核验 | 中低 | 适合成为中国高校场景的本地化壁垒 |
| 用户可见决策账本 | 低 | 适合成为技术、伦理和竞赛表达上的差异化支柱 |

## 四、核心竞品逐项研究

### 1. Daylio：情绪记录和统计的成熟基准

**公开产品事实**：官网展示两步选择情绪和活动、文字/照片/语音记录、列表与日历、搜索、图表、相关性、目标、习惯、提醒、备份和 PDF/CSV 导出；官网同时强调应用私有目录、PIN/指纹/Face ID 和不把日记条目发送到其服务器。官网显示“20M+ users”，这是企业自述，不等同于活跃用户或市场份额。

**与心晴相似**：低负担情绪记录、活动标签、趋势、目标、提醒、导出和隐私叙事。

**心晴应学习**：记录入口必须足够快，不能为了算法采集把用户逼成填写问卷。

**心晴不应硬拼**：记录速度、图表成熟度、定制图标、连续打卡和产品使用年限。

**可利用空位**：Daylio 的公开定位主要是“记录后看见生活模式”。心晴可以把记录继续向前推进到“当前状态允许做什么、何时应联系真实的人”，但不能把“Daylio 没有展示”写成它绝对没有。

### 2. Stoic：引导式反思和习惯养成的成熟基准

**公开产品事实**：官网展示每日反思、引导式日记、专家和治疗师启发的提示、趋势追踪、提醒、连续记录、徽章、事件活动、冥想和呼吸练习；同时展示 AI 个性化日记、设备端存储、3M+ 用户和 4.8 评分等信息。用户规模和评分为官网展示或应用商店信息，不能直接当作疗效证据。

**与心晴相似**：每日 check-in、日记、趋势、低负担练习、提醒、隐私。

**心晴应学习**：让反思行为自然地嵌入一天，而不是让用户进入一个复杂的心理测评流程。

**心晴不应硬拼**：提示内容数量、视觉完成度、徽章和情绪陪伴感。

**可利用空位**：Stoic 解决“今天写什么、做什么反思”；心晴可解决“当前状态是否允许普通自助动作、是否应该先连接支持”。

### 3. Bearable：多因素健康观察和自我实验基准

**公开产品事实**：官网展示症状与情绪、睡眠、压力、焦虑、疲劳、疼痛、习惯、相关性、模式、周/月趋势和 30 多种报告；还展示健康实验、数据加密、导出、删除、不出售数据，以及面向研究和企业的入口。

**与心晴相似**：多信号、相关性、报告、长期观察和隐私控制。

**心晴应学习**：多因素记录必须能够帮助用户回顾自己的生活，而不是只输出一个看起来精确的分数。

**心晴不应宣称的差异**：不能说“只有心晴能融合睡眠、活动、情绪”。Bearable 已经证明这类多因素观察是成熟能力。

**可利用空位**：心晴把相关性限制在个人节奏和下一步行动内，并明确区分“观察到的共同变化”和“已经证明的因果效果”；高风险与数据不足路径不允许用学习逻辑绕过安全策略。

### 4. MindDoc：个性化问答、课程和医疗化路径基准

**公开产品事实**：官网展示每天最多三次问题、个性化反馈、图形化模式、70 多个课程和练习、预防、治疗支持和持续照护，并称 Companion App 为欧盟 MDR I 类医疗器械、曾接受超过 1000 名参与者的临床研究评估，累计超过 3M 用户使用。

**与心晴相似**：重复 check-in、早期发现、模式反馈、个性化练习和长期记录。

**心晴应学习**：稳定的重复记录和结构化反馈可以形成长期价值。

**心晴必须保持的边界**：MindDoc 已进入医疗器械和治疗支持语境，心晴当前应继续定位为非诊断的大学生早期觉察与求助桥梁，不能模仿医疗化表述。

**可利用空位**：心晴强调偏离自己的节奏、数据不足时不下结论，并把状态直接连接到校园可信任成人和专业资源。

### 5. Wysa：匿名、AI、人工参与和机构部署基准

**公开产品事实**：Wysa 官网展示匿名、随时可用、证据支持、引导式转介、治疗间支持、人工参与、医疗系统和雇主部署；官网还强调 AI 不自行做决定、支持可解释和可辩护，并自述覆盖 105 个国家、6M 用户、45+ 论文等指标。

**与心晴相似**：匿名叙事、早期支持、安全边界、转介、非诊断定位。

**心晴不应硬拼**：AI 对话、临床内容库、机构销售能力、研究数量和专业网络。

**可利用空位**：Wysa 的优势是“可扩展的支持服务”；心晴可以把确定性政策层、个人基线、数据完整度和用户侧决策追踪做得更具体、更容易审查。差异不在“我们更安全”，而在“每次动作都能被规则、证据和测试解释”。

### 6. Youper：AI 情绪追踪与危机防护直接对标

**公开产品事实**：Youper 官网展示 AI 情绪聊天、心情追踪、反思和日记；同时公开自伤/自杀表达检测、危机资源转介、内容防护、AI 身份披露、系统不完美的限制说明和 18 岁以上年龄限制，并明确不提供医疗诊断、治疗或危机干预。

**与心晴相似**：情绪追踪、反思、安全优先、危机转介、明确的非医疗边界。

**心晴不应宣称的差异**：不能说“只有心晴有危机识别或求助入口”。

**可利用空位**：心晴不依赖生成式对话承担核心判断，而是用确定性策略保证高风险时普通动作在调用层被阻断；同时把睡眠、活动、连接感、基线和数据完整度纳入行动策略。

### 7. Headspace：内容、AI 陪伴和专业服务综合平台

**公开产品事实**：Headspace 公开展示引导式冥想、睡眠资源、专家课程、在线心理服务和 Ebb AI companion。Ebb 的公开介绍强调帮助用户书写想法、寻找感恩和换一个角度看问题。

**与心晴相似**：状态相关内容推荐、呼吸/睡眠/压力练习、AI 陪伴。

**心晴不应硬拼**：内容规模、品牌、专家课程、治疗服务和组织渠道。

**可利用空位**：Headspace 主要负责“给你内容和支持”，心晴负责“在当前数据和风险边界下，先判断普通行动是否适合”。心晴可以把音频和练习当作被策略允许的资源。

### 8. Tide：中文睡眠、专注、冥想和呼吸场景基准

**公开产品事实**：Tide 官网和应用商店公开定位为 Sleep、Focus、Meditation、Breath，围绕自然声音、睡眠、小憩、冥想、呼吸和专注提供内容。

**与心晴相似**：睡眠、呼吸、专注和低负担行动。

**心晴不应硬拼**：声音内容、计时器、自然场景、审美和订阅习惯。

**可利用空位**：Tide 提供练习本身，心晴可以判断当前是否适合练习，并记录行动后的主观变化。

### 9. 7 Cups：真人倾听、社区、AI 和咨询服务基准

**公开产品事实**：官网展示免费匿名 24/7 倾听、支持小组、论坛、成长路径、Noni AI counsellor 和付费专业治疗；官网显示大量消息、服务者和触达人数等平台累计数据。

**与心晴相似**：连接感、匿名支持、求助、轻练习和真实他人。

**心晴不应硬拼**：真人网络、社区规模、咨询师目录、持续对话和内容治理。

**可利用空位**：7 Cups 解决“有人可以听”，心晴可以解决“什么时候值得进入支持网络、我该找谁、怎样用最少暴露的信息开口”。

### 10. 壹心理：中文内容、测评、倾诉和咨询服务基准

**公开产品事实**：公开页面和应用商店信息展示心理科普、心理咨询、即时倾诉、心理测评、课程和咨询师服务；官网搜索摘要自述已服务大量用户和提供 24 小时服务。

**与心晴相似**：中文心理表达、评估、求助和专业资源连接。

**心晴不应硬拼**：专家数量、内容规模、咨询服务和平台运营。

**可利用空位**：把校园学生在正式求助前的状态观察、个人节奏、数据来源、行动门控和可编辑求助草稿做成更窄、更明确的前置层。

### 11. 简单心理：全周期专业服务基准

**公开页面和应用商店信息**：简单心理定位为一站式心理健康服务平台，公开展示心理评估、服务匹配、心理咨询师、心理课程、心理测试、免费心理热线和 AI 咨询助理等能力。

**与心晴相似**：评估、AI 陪伴、心理服务发现和求助连接。

**心晴不应硬拼**：专业服务网络、咨询匹配、课程、线下服务和咨询质量治理。

**可利用空位**：不把用户直接推向咨询交易，而是先在本机建立一段由用户控制的状态摘要，再由用户决定是否联系朋友、老师、家人或专业资源。

### 12. 心岛日记和中文树洞类产品：本土情绪社区基准

**公开产品事实**：心岛日记官网定位为温暖的情绪树洞和治愈社区，公开应用商店信息强调记录心事、倾诉、遇见共鸣和社区陪伴。中文市场的校园树洞、匿名倾诉、AI 树洞和“取暖”产品也在持续出现。

**与心晴相似**：匿名表达、情绪记录、共鸣、树洞和轻社交。

**心晴不应硬拼**：社区氛围、UGC 数量、回复速度和社交网络效应。

**可利用空位**：心晴的优势应是“从私密记录走向安全求助”，而不是把自己变成公共内容社区。当前漂流瓶应继续标注为本机演示海域，避免被理解为已上线的多用户心理社区。

#### 实时核验后的市场判断

1. **安全不是空白市场，而是执行质量的竞争。** Wysa、Youper、Headspace Ebb 都已经公开危机边界、转介或安全系统。心晴不能使用“市场上只有我们重视安全”这类表述；真正可验证的差异是：每个普通行动入口是否都经过同一策略层、高风险是否绝对阻断、数据不足是否绝对拒绝过度判断、用户是否看得见依据和分享范围。
2. **“记录—分析—建议”已经是成熟范式。** Daylio、Stoic、Bearable、MindDoc、Youper 覆盖了从轻量记录到多因素报告、个性化练习和 AI 反思。心晴的主流程应改写成“记录—判断数据是否足够—对比个人节奏—决定当前允许的下一步—必要时转接真实支持”。
3. **校园 Warm Handoff 是比“校园心理 AI”更稳的切口。** 本次直接核验的国际产品主要按通用消费者、企业、医疗机构或真人社区组织服务；它们都不是心晴当前要正面复制的校园资源配置与最小披露求助草稿。这个空位不是“竞品绝对没有”，而是心晴可以围绕中国高校的联系人、服务时间、校内入口和核验状态做本地化深挖。
4. **用户控制和可解释性应成为产品证据，而不是宣传口号。** 竞品普遍使用“匿名”“加密”“安全”“临床支持”等表述。心晴需要把这些词拆成可观察行为：本次判断读取了哪些字段、哪些字段缺失、为什么允许/阻断一个动作、求助草稿默认分享哪些内容、用户是否主动复制或发送。

## 六、心晴应该怎样定义自己的创新

### 1. 创新不是“多一个功能”，而是承接一个被忽略的用户任务

用户真正的问题通常不是：

> “我想要一个更漂亮的情绪记录工具。”

而是：

> “我感觉自己不太对劲，但我不知道这是不是值得求助，也不知道应该先做什么、找谁、怎么说。”

心晴的产品任务应该从“帮助用户感觉更好”改成更可验证的四步：

1. 帮用户看见自己是否偏离最近的正常节奏。
2. 帮用户知道当前结论有多可靠、缺了哪些信息。
3. 帮用户在安全边界内选择下一步，不把普通建议误用于高风险场景。
4. 帮用户把求助说清楚，同时保留对分享内容和发送动作的控制权。

### 2. 第一创新支柱：Policy-as-Product 的 Safety Gate

Safety Gate 不应只是“高风险页面上的一段提醒”，而应是产品的核心交互和工程合同：

```text
输入数据
  -> 数据完整度判断
  -> 危机信号门控
  -> 个人基线偏移
  -> 允许动作集合
  -> 页面和调用层共同校验
  -> 生成决策解释与证据
```

用户每次都应该能看到三句话：

- **为什么这样判断**：列出使用的信号和规则原因。
- **现在可以先做什么**：只显示当前策略允许的动作。
- **暂时不建议做什么**：显示被阻断的普通动作及其原因。

工程上必须做到：

- 所有普通行动入口都调用统一的 `canStartAction`/`assertActionAllowed`，不能只依赖页面跳转。
- 高风险路径只能允许 `help`，数据不足路径只能允许 `checkin`。
- 每次决策记录策略版本、决策编号、证据、数据来源、置信度和测试用例。
- 风险词测试要覆盖否定语境、隐喻、错别字、多段文本、引用他人原话和中英文混杂。
- 高风险和数据不足状态下，反馈学习不能修改安全边界。

当前实现已经在 `src/domain/evaluate-state.ts`、`src/rules/risk-assessment.js` 和 `src/security/risk-gate.js` 具备基础。下一步重点不是增加更多规则，而是证明没有任何入口能绕过这些规则。

### 3. 第二创新支柱：Personal Rhythm，而不是一个孤立的分数

RISE 需要从“今日得分”升级为“个人节奏观察”：

- 先建立基线，记录不足时明确显示“还在了解”，不要输出过度精确的偏移。
- 用 7 天、14 天等个人窗口展示变化，标明记录数量和缺失信号。
- 将“偏离自己”与“高风险”分开展示，避免用户把偏离等同于危险。
- 允许标记考试周、搬宿舍、旅行、疾病、实习和毕业等特殊时期，避免异常事件污染基线。
- 用自然语言说明变化，例如“睡眠比你最近常态少约 2 小时”，而不是只显示红色分数。
- 将置信度解释为“当前信息对这次判断的支持程度”，不能解释为疾病概率。

真正的差异不是“我们也有个性化”，而是：

> 个人基线会改变当前可执行的行动边界，而不只是改变一张趋势图的颜色。

### 4. 第三创新支柱：Campus Warm Handoff

求助桥应该成为心晴最有机会形成用户口碑的功能。建议设计成“最小披露分享包”，而不是把整段日记转发出去。

**用户可选择的对象**：朋友、老师/辅导员、家人、校心理中心或专业资源。

**用户可选择的需要**：先听我说、陪我保持联系、陪我一起找支持。

**用户可选择的紧迫程度**：现在需要、今天稍后、这周找时间。

**默认分享字段**：

- 最近一段时间的状态摘要
- 用户主动选择的趋势或睡眠/精力变化
- 当前希望对方提供的支持
- 用户自己编辑后的第一句话

**默认不分享**：

- 原始日记全文
- 原始危机关键词
- 不必要的设备、位置、联系人和身份信息
- 未经用户确认的历史记录

**安全交互原则**：

- 先预览，再复制或发送。
- 明确哪些信息仍留在本机。
- 不自动上报、不自动联系任何人。
- 高风险时把“联系真实的人”置于普通练习前，但不把应用包装成危机干预终点。
- 校内资源显示服务对象、时间、地区、最近核验日期和来源；超过核验窗口时显示过期提醒。

当前 `src/domain/types.ts` 已经存在 `HelpDraftEvent`、`HelpResources` 和资源核验字段，`src/features/settings/SettingsPage.tsx` 也已有资源配置基础。下一步应把配置能力转成可完成的 60 秒求助任务。

### 5. 第四创新支柱：把隐私变成“隐私收据”

“我们重视隐私”已经是市场通用话术。心晴需要让用户在每次判断和分享时都能核对：

- 本次用了哪些数据。
- 本次没有读取哪些数据。
- 哪些结论来自用户自报，哪些来自历史基线，哪些来自行动反馈。
- 哪些数据会离开设备。
- 分享包里具体包含哪些字段。
- 数据能否导出、删除和撤回。

建议在产品中加入“本次判断的数据收据”和“分享前预览”。生产版还需要：

- 使用加密数据库或平台安全存储，而不是仅依赖 IndexedDB。
- 设备锁、备份加密、恢复密钥和设备丢失流程。
- 原始心理文本默认不进入云端。
- 分享包默认最小化，并支持一次性或有效期。
- 明确云同步是关闭、加密同步还是未配置。

中国《个人信息保护法》将医疗健康等信息列为敏感个人信息，处理敏感个人信息需要具有特定目的和充分必要性，并采取严格保护措施。心理健康相关数据的产品竞争力不能只靠“匿名 ID”，而要靠最小化采集、最小化披露和可验证的控制权。

### 6. 第五创新支柱：个人行动记忆，而不是“证明疗效”

心晴可以在安全边界内记录：

- 用户完成了什么行动。
- 行动前后的主观状态变化。
- 行动难度。
- 用户是否愿意再次尝试。
- 这个动作是否适合当前情境。

但产品文案只能说“对你最近几次记录可能更合适”，不能说“这个动作治疗了你”或“证明有效”。这会形成一个轻量、可解释的个人行动记忆层，与内容平台的固定课程和 AI 的通用生成不同。

## 七、建议的产品架构与用户流程

### 主流程

```text
低负担记录
  -> 数据完整度卡片
  -> 风险门控
      -> 高风险：求助优先
      -> 数据不足：先补充记录
      -> 普通/中度：进入个人基线判断
  -> 显示允许动作与阻断动作
  -> 轻行动或求助表达
  -> 反馈与下一次个人化
```

### 首页应该表达的不是“分数多高”，而是状态决策

建议首页优先展示：

1. 当前状态：接近平时、出现节奏偏移、暂时无法判断、求助优先。
2. 依据：睡眠、情绪、活动、连接感和记录完整度。
3. 下一步：一个最小可执行动作或一个求助对象。
4. 限制：本次判断不代表诊断；数据不足时不下确定结论。

RISE 数字可以保留，但不应该压过状态语义、数据完整度和求助路径。

### 决策详情页应该回答五个问题

| 用户问题 | 产品输出 |
|---|---|
| 你为什么这样判断？ | Reason Code 和自然语言证据 |
| 你用了我的什么数据？ | 数据来源、时间窗口、缺失信号 |
| 这个结论有多可靠？ | 置信度和建立基线所需记录数 |
| 我现在可以做什么？ | 允许动作集合和第一步 |
| 我暂时不能做什么？ | 阻断动作和安全原因 |

## 八、创新优先级

### P0：必须先做

#### P0-1 Safety Gate 全入口执行

**目标**：把“高风险优先求助、数据不足先补充”从页面表达变成调用层不可绕过的策略。

**交付物**：

- 所有普通行动统一经过 `canStartAction`。
- 高风险、数据不足、普通波动、中度关注的策略快照。
- 危机词、否定、引用、错别字、隐喻、多轮输入测试集。
- 每次决策对应策略版本和回归用例。

**验证指标**：

- 高风险回归用例中普通动作阻断率目标为 100%。
- 数据不足用例不输出未经依据的个性化普通建议。
- 专业审核者能定位每条高风险文案的依据、边界和剩余风险。

#### P0-2 Campus Warm Handoff

**目标**：让用户在 60 秒内生成一段自己愿意发出的求助草稿。

**交付物**：

- 朋友、老师/辅导员、家人、心理中心四类对象。
- “听我说 / 陪我保持联系 / 陪我找支持”三类需要。
- 最小披露分享包预览。
- 校内资源的地区、时间、来源、核验日期和过期状态。
- 不自动发送、不自动上报的明确控制。

**验证指标**：

- 用户能在 60 秒内选择对象并完成草稿。
- 用户能准确说出分享了什么和没有分享什么。
- 用户能理解高风险时为什么普通练习不在第一顺位。
- 资源链接和服务时间的核验有效率达到可运营标准。

### P1：建立可持续差异

#### P1-1 Personal Rhythm 2.0

- 7/14 天基线窗口。
- 特殊时期标记。
- 记录数量、缺失信号和置信度。
- “偏离自己”与“高风险”分层表达。
- 基线不因一次异常记录自动重写。

#### P1-2 Privacy Receipt

- 本次判断数据收据。
- 分享包字段开关和预览。
- 原始备注默认不分享。
- 加密存储、备份和设备丢失方案。
- 云同步状态可见。

#### P1-3 Personal Action Memory

- 行动前后主观反馈。
- 完成难度和再次尝试意愿。
- 只在普通安全路径中学习。
- 不将个体变化包装为临床效果。

### P2：有证据后再做

- 端侧辅助模型，仅作为线索，不直接决定风险和处置。
- 面向学校的资源和策略配置后台。
- 面向研究的去标识化、聚合导出。
- 可插拔的内容资源市场。
- 支持者协作模式，但必须由学生明确授权。

### 暂缓或禁止作为主线

- 公共漂流瓶和匿名树洞规模化运营。
- 班级、宿舍、学院个人风险排行或热力图。
- 自动联系辅导员、家人、老师或报警。
- 诊断标签、治疗承诺、危机预测承诺。
- 用连续打卡、徽章和排名驱动心理健康使用。

## 九、商业与落地策略

### 推荐的切入顺序

1. **学生端免费或低门槛使用**：建立信任，重点验证记录负担、解释理解度和求助表达价值。
2. **校园资源配置服务**：学校或心理中心只配置热线、服务时间、校内入口和安全文案，不默认读取学生原始记录。
3. **可审查的早期觉察 SDK/模块**：向已有校园平台、健康教育平台或研究项目提供策略层和求助桥，而不是直接卖个人数据。
4. **研究与专业审核合作**：积累规则可用性、安全事件、用户理解度和资源转接证据，不提前声称疗效。

### 不推荐的商业化方式

- 以用户心理文本换广告或精准营销。
- 向学校出售个人风险名单。
- 以“越严重越应该付费”为增长设计。
- 没有专业团队和审核能力就运营公共危机社区。

### 适合心晴的商业护城河

不是内容库存，也不是模型参数，而是：

- 可配置的校园资源和资源核验机制。
- 可回归测试的心理安全策略库。
- 用户可见的决策与数据账本。
- 在不收集不必要原始文本的前提下，积累“什么样的下一步被用户理解、接受和完成”的证据。
- 经过真实学生试用和专业审核后形成的场景、文案和治理规范。

## 十、验证方案：把创新从概念变成证据

### 用户试用设计

沿用项目已有的匿名试用执行包，建议把竞品差异化验证任务加入 10-20 名大学生、连续 3-5 天的试用：

1. 完成一次低负担记录，记录完成时间和主观负担。
2. 让用户用自己的话解释 RISE 或个人节奏状态的来源。
3. 让用户指出当前允许的动作和暂时不建议的动作。
4. 对比普通波动和高风险演示场景，观察用户是否找到不同的下一步。
5. 生成一段发给朋友、老师或家人的求助草稿。
6. 让用户指出分享包中哪些信息会离开本机。

### 关键假设和指标

| 假设 | 核心指标 | 不能替代的证据 |
|---|---|---|
| 用户愿意低负担记录 | 首次完成率、完成时间、主观负担 | 临床依从性证明 |
| 用户理解个人状态 | 能复述至少两个依据、理解度 | 诊断准确性 |
| 用户理解 Safety Gate | 能区分普通波动、高风险和数据不足路径 | 危机预测能力 |
| 求助草稿降低表达成本 | 草稿完成时间、自然度评分、愿意使用程度 | 实际危机处置效果 |
| 最小披露增加信任 | 用户能正确识别分享字段、隐私清晰度评分 | 绝对隐私安全 |
| 个体行动记忆有价值 | 再次尝试意愿、行动完成率、前后主观反馈 | 因果疗效 |

### 专业审核重点

应请心理中心老师、辅导员或具备相关经验的专业人士审核：

- 危机词、否定语境和安全短语。
- 中度关注是否过度升级。
- “风险”“恢复指数”“偏离”等词是否可能造成诊断误解。
- 高风险求助页面是否足够具体、不过度恐吓。
- 求助草稿是否责备、命令或过度承诺。
- 校内资源缺失、过期、地区不匹配时的兜底文案。
- 试用者表达高风险时的停止试用和转接流程。

## 十一、90 天落地路线

### 0-30 天：把差异做成稳定演示

- 完成 Safety Gate 全入口审计。
- 建立危机文本、否定、边界和数据不足回归测试集。
- 把首页主视觉从“分数”调整为“状态 + 依据 + 下一步”。
- 完成 Warm Handoff 草稿、分享预览和资源过期状态。
- 保留漂流瓶本机演示边界，不开放未治理的多用户社区。

### 31-60 天：完成真实用户与专业审核

- 执行 10-20 名大学生匿名试用。
- 完成 1-2 名心理中心老师、辅导员或相关专业人员审核。
- 记录真实的理解度、表达成本、资源可用性和风险事件。
- 只把已完成的证据写入答辩材料，不把合成数据写成用户结果。

### 61-90 天：形成可复制的校园版本

- 增加 7/14 天基线和特殊时期标记。
- 完成隐私收据和分享字段最小化。
- 补充加密存储、备份恢复、设备丢失和数据删除设计。
- 形成“校园资源配置模板 + 策略版本 + 审核记录”三件套。
- 评估一个真实校园合作试点，不先做个人风险看板。

## 十二、最终定位与答辩口径

### 一句话定位

> 心晴 MindPulse 不是心理诊断工具，也不是另一个 AI 聊天机器人；它是面向大学生的端侧匿名早期觉察与求助桥梁，帮助用户看见偏离自己节奏的变化，知道当前安全的下一步，并把求助说出口。

### 30 秒差异化表达

> 市面上的情绪日记擅长记录，冥想 App 擅长提供内容，AI 陪伴擅长对话，心理服务平台擅长连接专业人员。心晴把它们之间缺少的一层做成核心：先用个人基线和多信号观察理解“我是否偏离了自己的节奏”，再用 Safety Gate 决定普通行动是否适合，最后把状态转成一段由用户控制的求助表达。高风险时普通推荐会被系统阻断，数据不足时系统会先承认“不够了解”，而不是装作给出答案。

### 不建议使用的主张

| 不建议说 | 建议改成 |
|---|---|
| 我们比其他产品更懂你的心理 | 我们展示个人节奏变化和判断依据 |
| AI 心理医生 | 端侧状态观察与求助桥梁 |
| 诊断焦虑/抑郁 | 识别需要进一步关注的信号，不做诊断 |
| 我们能预测危机 | 我们在高风险信号出现时优先连接人工和专业支持 |
| 只有我们有 Safety Gate | 我们把安全闸门做成可审计、可回归测试、不可被普通入口绕过的策略层 |
| 证明某个练习有效 | 记录用户完成行动后的主观反馈 |
| 绝对保护隐私 | 本地优先、最小披露、可导出和可删除；正式版仍需完成加密和治理 |
| 我们有全校心理风险热力图 | 经用户授权的资源配置和聚合研究，不追踪个人、不做排名 |
