# 心晴 MindPulse 单文件 Web 原型 · 审查报告

审查对象：`心晴MindPulse_Web原型.html`（3825 行）
审查维度：交互与视觉细节 / 可访问性 / 心理安全与文案边界 / 代码与工程质量
日期：2026-08-03
验证方式：静态代码审读 + Playwright 无头浏览器实测（430×932 等 5 种视口）

---

## 结论摘要

原型的决策链路（DecisionTrace、Safety Gate、个人基线归因）设计完整度明显高于一般竞赛原型，可解释性做得扎实。本轮发现 1 个已在浏览器中实测触发的注入缺陷、若干可访问性硬性不达标项，以及 2 处安全策略覆盖不全。下面按优先级排列，每条都标注了证据来源（实测 / 静态）。

## P0 · 建议在下一次对外演示前修复

### 1. 签到备注输入框存在可实测触发的 XSS（第 3223 行）

第 4 步"要不要顺手写一句？"的 textarea 直接把 `S.ciTxt` 拼进 HTML，未经 `esc()`：

```js
'<textarea class="field" rows="4" id="checkInput" placeholder="...">'+S.ciTxt+'</textarea>'
```

**已实测触发，且不依赖任何调试接口。** 纯 UI 路径：

1. 首页点底部签到 → 选情绪 → 填三个信号 → 继续到第 4 步
2. 在备注框输入 `</textarea><img src=x onerror="window.__XSS=1">`
3. 点「上一步」再点「继续」

`上一步` / `继续` 都会调用 `rerenderCheckin()`，重新把草稿拼回 textarea，payload 断出标签并执行。实测结果：`window.__XSS === true`，DOM 中出现注入的 `img` 节点。

值得说明的是，`esc()` 函数第 897 行就有，全文调用了 75 次，时间线渲染（第 1298 行）也正确转义了。这是个别遗漏，不是整体缺失。修复只需包一层 `esc(S.ciTxt)`。

现实影响相对可控——单机原型、payload 来自用户自己输入、localStorage 中未发现残留（备注保存时走了另一条已转义路径）。但评审现场如果有人当场输入，行为不可预期，值得先补掉。

## P1 · 影响评审印象或存在扩散风险

### 2. 日记输入框同类隐患（第 3719 行）

`S.journalDraft` 同样未转义。当前正常 UI 走不通——「再写一篇」会先把草稿清空再重渲染，所以草稿非空时不会重新拼接。属于潜伏问题：一旦后续任何人加一次重渲染调用，它就会变成和第 1 条一样的活缺陷。建议一并转义。

### 3. 日详情弹层是不可达的死代码（第 3184-3191 行）

`renderDayDetail()` 读 `S.dd`，但全文搜索 `S.dd` 只有四处：一处判断、一处读取、两处置 `null`，**没有任何赋值为真值的地方**。也就是说这个"点日历某天看当天详情"的功能完全无法触发。

两层问题：一是功能缺失（日历上点某天没有反应）；二是这段代码里 `day.text` 也未转义，属于潜伏注入点。要么补上入口并转义，要么整段删掉。

### 4. 覆盖层（sheet / modal）缺少无障碍语义与焦点管理

实测签到 sheet 打开后：

| 检查项 | 实测结果 |
|---|---|
| `role` | `null`（应为 `dialog`） |
| `aria-modal` | `null` |
| 焦点是否移入面板 | 否，仍停在 `BODY` |
| 连按 8 次 Tab | 8 次全部落在面板**外**（首页按钮和底部导航） |
| 按 Esc | 无反应，sheet 仍在 |

对键盘和读屏用户，弹层等于不可用：焦点从未进入，Tab 在背后的页面里游走，Esc 关不掉。涉及 WCAG 2.1.1（键盘可达）、2.4.3（焦点顺序）、4.1.2（名称/角色/值）。

### 5. 禁用了页面缩放（第 5 行）

```html
content="width=device-width,initial-scale=1,maximum-scale=1,user-scalable=no,viewport-fit=cover"
```

`user-scalable=no` + `maximum-scale=1` 直接违反 WCAG 1.4.4（文本可调整至 200%）。低视力用户无法放大。移除这两个参数即可，实测 5 种视口（320/360/375/430/768 宽）均无横向溢出，放开缩放不会破坏布局。

### 6. 底部导航中心按钮没有可访问名称

实测：`text=""`、`aria-label=null`、`role=null`。读屏用户只会听到"按钮"。这是应用最主要的操作入口。WCAG 4.1.2。

### 7. toast 提示读屏不可感知

第 2077-2091 行的 `toast()` 创建裸 `div`，实测 `role=null`、`aria-live=null`。这意味着"已记录此刻"、以及**"Safety Gate 已阻断普通行动，先进入求助入口"**这类关键安全提示，读屏用户完全收不到。安全相关提示尤其应该补 `role="status"` 或 `role="alert"`。

### 8. 正文对比度不达标（实测计算）

| 元素 | 字号 | 对比度 | 要求 | 结果 |
|---|---|---|---|---|
| `.status-kicker` | 13px | 2.91:1 | 4.5 | ✗ |
| `.nb-sub` | 12px | 3.52:1 | 4.5 | ✗ |
| `.decision-signal-label` | 10px | 3.88:1 | 4.5 | ✗ |
| `.decision-signal-delta` | 10px | 4.64:1 | 4.5 | ✓ |
| `.status-line` | 16px | 5.30:1 | 4.5 | ✓ |

三项不达标，均为小字号说明性文字（WCAG 1.4.3）。另外 10px 正文本身偏小，建议同时上调到 12px 以上。

### 9. Safety Gate 的阻断清单不完整（第 2449 行）

```js
if(trace.mode==="HIGH_RISK"&&["map","workspace","companion"].indexOf(next)>=0){...}
```

只拦 `map` / `workspace` / `companion`。而实测标签页共 6 个：首页、趋势、待办、记录、陪伴、求助——`bottle`（漂流瓶）、`memo`、`schedule`、`settings`、`rules` 都不在清单里。高风险状态下用户仍可进入漂流瓶等社交向功能。

这里的写法是"黑名单"，而 Safety Gate 的设计意图是"非绕过的策略层"。建议改为白名单：高风险下**只**允许 `help` 及少数必要页面。这既是安全问题，也是评审可能会追问的设计一致性问题。

### 10. 风险判定只看最后一条记录（约第 1125 行）

```js
var latest=safeRecords[safeRecords.length-1]||{};
var d=detectDanger(text(latest)+" "+(currentText||""));
```

如果用户三天前写下危机内容、今天记了一条正常的，`assessRisk` 只读最新那条，历史危机信号不参与判定。对一个以"求助路径"为核心的产品，建议至少在近 N 条记录上做滑窗。

### 11. 调试接口随生产 HTML 一起发布（第 2017 行）

`window.MindPulseDebug` 暴露了 `openIntervention` / `openAction` / `completeCurrentCompanionStep` / `currentDecisionTrace`。其中 `openAgent` 加了 HIGH_RISK 守卫，但 `openIntervention` 和 `openAction` 没有——可以绕过 Safety Gate 直接打开干预。演示版建议用构建开关剥离，或至少给所有入口补上同样的守卫。

## P2 · 打磨项

### 12. "高置信度"与"合成演示"并列显示

首页实测渲染文案：

```
数据完整度  100% · 高置信度      数据来源  合成演示
```

`completeness` 的算法是四个字段的填充率（第 2543 行），衡量的是"字段填没填满"，不是"数据可不可信"。演示数据填满四个字段就显示"高置信度"，和右边"合成演示"放在一起会显得自相矛盾。建议把"高置信度"改成描述完整度的措辞（如"字段完整"），或在数据来源为合成时强制降档。

### 13. 偏移数值没有方向符号

实测首页：

```
睡眠  5.4h / 基线 5.4h   →  偏移 0%
活动  4600 / 基线 3953   →  偏移 16%
连接  52% / 基线 32%     →  偏移 20 点
```

活动 4600 是**高于**基线 3953 的，但"偏移 16%"和"低于基线 16%"在视觉上无法区分。用户读不出方向。建议显示 `+16%` / `-16%`，或直接写"高于/低于基线"。

### 14. 基线相对化可能把不健康的绝对值说成正常

首页实测：睡眠 5.4h、基线 5.4h、偏移 0%，标题"今天的节奏接近个人基线"。

逻辑上没错——`flags` 的阈值全是负向的（睡眠 ≤-25%、步数 ≤-40%、社交 ≤-20、情绪 ≤-1），5.4h 持平确实不触发标记。但产品语义上，长期 5.4h 睡眠被表述为"接近正常节奏"，是把不健康状态正常化了。建议对睡眠这类有公认健康区间的指标加一条绝对下限提示，例如"和你平时接近，但连续低于 6h 值得留意"——保留个人基线框架，同时不掩盖绝对风险。

### 15. 登录后过场动画 ~3.3 秒且无法跳过

实测登录后出现"正在整理你的节奏信号"过场页，持续约 3348ms，**期间无任何可点击元素、无跳过入口**。评审现场每次进入都要等 3 秒多。建议缩短到 1 秒内或允许点击跳过。

### 16. 待办/记录页的操作按钮小于 44px

实测：`task-check` 28×28、`task-delete` 31×31（两个标签页各 2 组）。低于 44×44 的推荐最小触摸目标。其余 4 个标签页无此问题。删除按钮尤其值得放大——误触的是不可逆操作。

### 17. 安全短语正则三处重复

同一组正则出现在三个文件：

- `心晴MindPulse_Web原型.html:1093`
- `src/domain/decision-policy.js:28`
- `src/rules/browser-engine.js:47`

三份独立维护，改一处漏两处的风险很高。而且用了贪婪匹配 `/不想活[着得].*但是/`，`.*` 跨越很长文本时可能误判。建议收敛为单一来源，并把 `.*` 限定长度（如 `.{0,15}`）。

### 18. "单文件原型"实际依赖 5 个外部脚本

第 724-728 行加载了 `src/rules/browser-engine.js` 等 5 个文件（实测均存在）。单独拷贝 HTML 到别处会直接失败。如果"单文件可分发"是评审卖点，需要内联；如果不是，建议在文档里改掉"单文件"的表述。另外 `favicon.ico` 缺失，控制台有一条 404（无害，但演示时控制台不干净）。

### 19. 图标全部使用 emoji

🗒 / 📅 / 🫁 等依赖系统字体。无头环境中渲染为豆腐块——这是环境差异，不算缺陷，但提示了真实风险：不同设备、尤其是较旧的 Android 和 Windows，emoji 字形差异很大，评审用机上可能和你本地看到的不一样。关键图标建议改用内联 SVG。

## 两处更正

审查过程中我有两个中途判断在深入验证后被推翻，一并说明：

1. **日详情弹层的 `day.text` 未转义，我一度判为"存储型 XSS / P0"。** 实际不成立——`S.dd` 从未被赋真值，整个弹层不可达（见第 3 条）。它是死代码里的潜伏点，不是可利用漏洞。

2. **首页"标题说接近基线、但信号显示偏移 16%/20 点"，我一度判为逻辑矛盾。** 实际不矛盾——那两个偏移都是正向（高于基线），而 `flags` 阈值只对负向偏离触发，所以标题正确。真正的缺陷是偏移值缺少方向符号（见第 13 条）。

## 验证方法与未覆盖范围

**已实测**：XSS 触发路径、覆盖层焦点/Tab/Esc 行为、对比度（前景+实际背景计算）、触摸目标尺寸（6 个标签页全覆盖）、5 种视口横向溢出（均通过）、过场动画时长、导航按钮可访问名称、toast 语义、外部依赖存在性、运行期控制台错误（仅 favicon 404）。

**未覆盖**：真实读屏软件（NVDA / VoiceOver）验证——自动化只能测属性，实际朗读体验需人工验证；真实移动设备上的 emoji 渲染与触摸手感；`src/` 下的 React 实现（本轮按约定不在范围内）。

**需要说明的是**：本报告是代码与界面层面的技术审查。项目文档中记录的 3 人用户走查与专业心理评审仍处于你此前确认的暂缓状态，本轮未涉及，也不构成对文案临床适当性的专业意见——第 14 条关于睡眠表述的建议属于产品逻辑观察，不是专业心理学结论。
